Recuperación: el responsable técnico verifica la identidad del cliente y gestiona el restablecimiento desde Supabase Auth mediante un procedimiento seguro. Recuperación por soporte (prueba local):
- Mantener Site URL y Redirect URLs en http://127.0.0.1:5500/index.html mientras se prueba con Live Server. El index deriva los enlaces de recuperación a recovery.html. En producción, usar la URL HTTPS definitiva y retirar las redirecciones locales.
- Desde Authentication > Users, enviar un correo nuevo de recuperación. Abrirlo en el ordenador con Live Server activo. No compartir el enlace ni el token. La pantalla acepta el flujo implícito de recuperación de Supabase y verifica el usuario administrador con Auth. No utiliza una sesión de administración existente y no persiste la sesión de recuperación.
- Una vez cambiada la contraseña, se solicita cierre de sesiones global (los tokens de acceso existentes pueden seguir válidos hasta su expiración). Si falla, cerrar la pestaña. Verificar el acceso con la nueva contraseña. Usar una contraseña temporal si se entrega al cliente y pedirle cambiarla desde Seguridad; nunca enviarla por WhatsApp.
- El correo profesional permanece bajo control del técnico; la pantalla no se enlaza desde la navegación ni sustituye el contacto de WhatsApp. La URL no es un secreto: la autorización depende de Supabase. Si el propietario cambia de cuenta o UID, revisar esta configuración, el administrador y RLS.
- Pruebas locales simuladas de JavaScript: enlace ausente/caducado, usuario no autorizado, confirmación de contraseña, actualización y cancelación. La ejecución real en Supabase y el navegador del cliente están pendientes. El navegador de pruebas del entorno no permitió abrir páginas.
